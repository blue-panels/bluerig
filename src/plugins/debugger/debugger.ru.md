# Debugger <!-- help:notitle -->

**Отладчик**

Запускает программу проекта под GDB или отладочным адаптером ее языка:
ставит точки останова на полях, делает шаги в окне исходного текста и
показывает рядом стек вызовов, переменные и наблюдаемые выражения.

|  |  |
|--|--|
| Shift-F9 | Собрать и запустить или продолжить |
| Ctrl-F8, Ctrl-B | Поставить или снять точку останова |
| Alt-F6 | Условие точки останова |
| Alt-F5 | В панель отладчика и обратно |
| Ctrl-F2 | Во время сеанса: остановить программу. Вне сеанса: сохранить файл под другим именем |

Эти клавиши действуют в любом окне файла. Клавиши можно переназначить в секции
*[debugger]* файла *~/.config/bluerig/keymap.ini*, например
*DebugStepOver = alt-o*; *f15* там - это Shift-F5, *f17* - Shift-F7, *f18* -
Shift-F8. Команды есть и в меню Debug.

**Первый запуск**

При первом запуске отладчик сам составляет конфигурацию и показывает форму
Debug configuration: программа, ее аргументы, каталог, окружение, GDB,
параметры ctags и сборка перед запуском. Enter принимает форму.

|  |  |
|--|--|
| Проект | Тот, что находит плагин Файлы проекта, или выбранный в Project > Open project... |
| Программа | Собранная плагином Сборщик с отладочной информацией; из нескольких - список, новые первыми |
| Язык | Из *presets.ini*: GDB, программа до первой сборки, адаптер; для Rust - rust-gdb |

О программе без отладочной информации или собранной с оптимизацией
отладчик сообщает и называет команду сборки для отладки.

Если в конфигурации включена сборка перед запуском, отладчик сначала
собирает проект. Если сборка не удалась, Alt-J переходит к ошибкам.

Аргументы и окружение разбиваются как в shell, но shell их не выполняет:
*GREETING="hello world"*.

**Пошаговый режим**

В пошаговом режиме окна исходного текста принимают клавиши отладчика
и на остановке, и пока программа выполняется между остановками. Клавиши
движения, поиска и выделения остаются клавишами редактора, а правка текста
дает звуковой сигнал. Esc возвращает к правке до следующей остановки.

|  |  |
|--|--|
| F5, Shift-F9 | Продолжить |
| Shift-F6 | Приостановить |
| F7 | Шаг с заходом |
| F8 | Шаг с обходом |
| Shift-F8 | Шаг с выходом |
| Shift-F7, Ctrl-F7 | Шаг с заходом на одну инструкцию |
| Shift-F4 | Шаг с обходом на одну инструкцию |
| F4, Alt-F9 | Выполнить до строки курсора |
| F6 | Поставить или снять точку останова |
| Alt-F8 | Вычислить выделение или слово под курсором |
| Alt-F10 | Вернуться к строке остановки |
| F3 | Переиндексировать символы проекта |
| Shift-F5, Ctrl-F2 | Остановить программу |
| Esc | Вернуться к правке до следующей остановки |

F2, F9 и F10 остаются сохранением, меню и выходом. В пошаговом режиме
Shift-F7 и Shift-F4 выполняют шаг на одну инструкцию, когда программа
остановлена. Вне пошагового режима это повторный поиск и повторная замена.

Клавиши взяты из IntelliJ IDEA там, где редактор их не занимает; F5 и F4
добавлены, потому что F9 и F10 заняты меню и выходом.

**Режим отладки**

*bluerig -D каталог* открывает проект для отладки: последний файл проекта,
справа дерево проекта и панель отладчика под ним. В этом режиме окна файлов
всегда принимают F3-F8 отладчика, а текст правится как обычно. Окна > Debug
keys in files включает этот режим без *-D*. Перед выходом редактор
спрашивает подтверждение.

При запуске окна расставляются по расположению *Debug*: дерево и панель
справа, консоль внизу. После отладки окна возвращаются на место. Окна >
Layout... меняет или выключает это.

**Программа в терминале**

С флажком Run in a terminal window программа выполняется на вкладке Program
внизу: там ее вывод, и туда идут все клавиши. Если шаг длится дольше 0,3 с,
фокус переходит на вкладку, а после остановки возвращается в файл. Alt-F5
переходит из вкладки в панель. Без флажка вывод идет в консоль, а Send
line... меню Debug передает программе строку.

**Панель отладчика**

Справа: состояние программы, Locals, Registers, Watches, Call stack и
Breakpoints. Под строкой остановки *ran 0.004 s* - время от шага до
остановки, вместе с работой отладчика. Окна > Debugger panel и Окна > Debug
console открывают их снова.

|  |  |
|--|--|
| Up, Down, PgUp, PgDn, Home, End | Двигаться по строкам |
| Right, Left | Раскрыть или свернуть |
| Enter | Раскрыть, показать значение, перейти к кадру или точке останова |
| Space | Отключить или включить точку останова |
| Ins | Добавить выбранную переменную или её поле в наблюдаемые выражения. На остальных строках открывает ввод выражения |
| Del | Удалить наблюдаемое выражение или точку останова |
| Alt-F6 | Условие точки останова |
| : | Команда GDB или консоли адаптера |
| F10 | Закрыть панель |

Значение, которое изменил шаг, показано желтым и отмечено *\**, новое -
зеленым и отмечено *+*, ошибка - красным. Раскрытые значения остаются
раскрытыми от остановки к остановке. Регистры запрашиваются, только пока
раздел раскрыт, и показываются сами в коде без исходного текста.

Цвета и отметки панели задает секция *[debugger]* скина: *title*,
*changed*, *added*, *error*, *internal*, *changed-char*, *added-char*,
*arrow*.

**Значения в тексте**

Пока программа остановлена, строки функции до строки остановки показывают
после текста значения названных в них переменных, а в ассемблере - регистры.
Цвет задает *editnote* в секции *[editor]* скина.

**Отметки на полях**

|  |  |
|--|--|
| o | Точка останова |
| - | Отключенная точка останова |
| c | Точка останова с условием |
| ? | Точка останова, которую отладчик еще не принял |
| > | Строка остановки |
| @ | Строка остановки с точкой останова |

Так отметки выглядят без скина. Свои символы задает секция *[widget-editor]*
скина, в darkfar это круги и ромб, а цвета - секция *[editor]*.

Точка останова сдвигается вместе со своей строкой. На строке без кода она
переходит на следующую строку с кодом.

**Условие точки останова**

Alt-F6 задает условие на языке программы: *i == 7*, *x > 2 and y*.
Программа останавливается, только когда условие истинно. Пустое условие
делает точку обычной. Панель показывает условие:
*loop.c:7 main if i == 7*.

**Меню Debug**

|  |  |
|--|--|
| Breakpoint on function... | Точка останова на функции проекта по имени |
| Run to function... | Продолжить до функции |
| Call stack... | Выбрать кадр стека |
| Evaluate expression... | Вычислить выражение, как Alt-F8 |
| Add watch... | Добавить наблюдаемое выражение |
| Exceptions... | На каких исключениях останавливаться |
| Send line... | Передать строку программе |
| Stop | Завершить сеанс |

Функции по имени берутся из индекса плагина Ctags. Наблюдаемое выражение
показывает значение, но не останавливает программу при его изменении.

Exceptions... предлагает виды, которые знает отладчик: для GDB - C++
исключения при выбросе или перехвате, для debugpy - raised, uncaught и
user uncaught. Пока ничего не выбрано, адаптер останавливается на своих
видах.

**Инструкции**

Окна > Disassembly показывает под исходным текстом инструкции функции
кадра, строки исходного текста перед своими инструкциями. Окно открывается
само при остановке в коде без исходного текста.

|  |  |
|--|--|
| Up, Down, PgUp, PgDn, Home, End | Двигаться по инструкциям |
| F6 | Точка останова на инструкции |
| Enter | К строке исходного текста |

Если обычный шаг приводит в код без исходного текста (например, в
*printf*), отладчик пытается выйти из этого кода. При шаге на одну
инструкцию автоматический выход не выполняется.

**Конфигурации**

Project > Debug configurations... показывает конфигурации проекта, а
звездочка отмечает ту, которую запускает Shift-F9. С флажком Keep in the
project они хранятся в *.bluerig/debug.ini* проекта, иначе - в настройках
пользователя. Точки останова и наблюдаемые выражения хранятся в настройках
пользователя.

**Отладочные адаптеры**

В форме Debug configuration выбор Debug adapter вместо GDB запускает
программу через адаптер Debug Adapter Protocol:

|  |  |
|--|--|
| Adapter | Команда адаптера |
| Address | host:port адаптера; с портом 0 порт берется из вывода команды |
| Launch (JSON) | Члены запроса запуска, например {"justMyCode": false} |

Адаптер берется по типу файла из *presets.ini*:

|  |  |
|--|--|
| .py | python3 -m debugpy.adapter |
| .sh, .bash | bash-dap |
| .go | dlv dap --listen=127.0.0.1:0 |
| .js, .mjs, .ts | js-debug-adapter 0, адрес 127.0.0.1:0 |
| программа | gdb -i dap |

Если адаптера нет, отладчик сообщает, как его установить. Программа на Go -
это пакет с *package main* в каталоге файла или выбранный из списка.

**Python**

debugpy ставится пакетом python3-debugpy или *pip install --user
debugpy*. Проект с *.venv*, *venv*, *.env* или *env* отлаживается своим
Python, при этом debugpy должен быть установлен и там. Сценарию, который
читает ввод, нужен терминал программы:
*{"console": "integratedTerminal"}*.

**Shell**

bash-dap отлаживает сценарии bash, ему нужен только Python 3: *pipx install
bash-dap*. Сценарий выполняется в терминале программы и останавливается и
в функциях внутри *$(...)* и конвейеров.

Отладчик выполняет одну локальную программу за раз.
