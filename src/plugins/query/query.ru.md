# Query <!-- help:notitle -->

**Запросы**

Выполняет запросы файла в MongoDB или PostgreSQL и показывает ответ внизу
экрана: сообщения базы и таблицу документов или строк. Показывает схему
базы, пишет запросы с помощью ИИ и записывает строки в файлы. Работает
только в *bluerig -Q*.

|  |  |
|--|--|
| F5 | Выполнить выделение, иначе запрос под курсором, иначе файл |
| Ctrl-F5 | Выполнить весь файл |
| F5, Esc | Во время запроса: остановить его |
| F6 | Написать запрос с помощью ИИ |
| Ctrl-F6, Alt-X | Записать все строки запроса в файл |
| Ctrl-Alt-S | Показать или спрятать окно Схема |
| Ctrl-Alt-PgDn, Ctrl-Alt-PgUp | Следующая, предыдущая вкладка ответа |
| F11 | Меню запросов |

Клавиши меняются в секции *[query]* файла привязок клавиш. Команды есть и в
меню Запрос. У QueryRollback (*ROLLBACK*) клавиши по умолчанию нет.

Какая база, задает *MC_QUERY_KIND*: *mongo* или *postgres*. Без нее
*MC_MONGO_URI* означает MongoDB, а файл *.sql* - PostgreSQL. Если файл не
указан, запросы хранятся в *~/.local/share/bluerig/queries/*, в файле с
именем базы, а для PostgreSQL - в *postgres/*, в файле с именем подключения
и базы.

**Файл запросов**

В MongoDB строка *// ---* начинает новый запрос, слова после черточек
называют его, а F5 выполняет часть, в которой стоит курсор, как один скрипт.
В PostgreSQL F5 выполняет выделение, иначе весь файл, одной транзакцией,
если в нем нет своего *BEGIN*.

```
// --- the last orders
// @table
db.orders.find({ status: 1 }).sort({ ts: -1 })

// --- how many
db.orders.countDocuments({ status: 1 })
```

|  |  |
|--|--|
| // @table | Показать во вкладке Таблица и значение, которым кончается запрос |
| // @limit 20 | Ограничить документы запроса, без числа - до 100 |

*@limit* добавляет *.limit()* к *find()* или стадию *$limit* к
*aggregate()*, при этом файл остается как есть.

**Вкладки ответа**

|  |  |
|--|--|
| Вывод | Что напечатала база: строки запроса, время, сервер, ошибки |
| Таблица | Документы или строки по столбцам: первые 100, посчитаны все |
| История | Версии файла запросов при каждом запуске |

Ошибка помечает свою строку в файле, и курсор переходит туда. В PostgreSQL
первая строка Вывода показывает и состояние транзакции: *[TX]*, пока она
открыта, и *[СБОЙ ТРАНЗАКЦИИ: нужен ROLLBACK]*, когда ее команда не
удалась.

Каждый запуск сохраняет файл как версию в
*~/.local/share/bluerig/queries/.history/*, хранятся 200 новейших. В
Истории:

|  |  |
|--|--|
| Enter, двойной щелчок | Вернуть файл к этой версии (Undo отменяет) |
| F3 | Сравнить версию с файлом (diff -u во вкладке Вывод) |
| F5 | Выполнить запрос версии, не меняя файл |
| Ctrl-Ins | Скопировать отмеченный текст |

Текущий текст перед переходом к версии сохраняется строкой *текущая*, при
этом Enter на ней возвращает его.

**Меню запросов**

F11 в файле *.sql* или *.js* открывает меню вместо меню пользователя:
EXPLAIN запроса, число строк запроса, строки *// @table* и *// @limit*,
выделенное заглавными или строчными, правка меню. Меню берется из
*query-menu.ini* bluerig, а *~/.config/bluerig/query/query-menu.ini*
заменяет его. Пункт может запускать свою команду: запрос у нее на stdin,
*BLUERIG_QUERY_KIND* в окружении. EXPLAIN ANALYZE выполняет только
SELECT, VALUES и TABLE.

**Схема**

Ctrl-Alt-S показывает справа дерево базы. Для MongoDB - базы, коллекции с
числом документов, представления, временные ряды, а у раскрытой коллекции -
поля по выборке из 100 документов, индексы и валидатор. Для PostgreSQL -
схемы, таблицы, представления, последовательности и функции, а у раскрытого
отношения - столбцы, ключи, внешние ключи, индексы, ссылки и триггеры.

|  |  |
|--|--|
| Enter, Right, Left | Раскрыть или свернуть узел |
| F5 | Первые 100 строк во вкладку Таблица |
| F3 | Вставить запрос строк в файл запросов |
| F4 | Вставить DDL в файл запросов: DROP (закомментирован) и CREATE |
| Insert | Вставить имя узла у курсора |
| Ctrl-F6, Alt-X | Записать все строки в файл |
| F2 | Подключиться заново и перечитать схему |
| F10, Esc | Закрыть окно |

DDL - это определение, а не резервная копия: в нем нет владельца, прав,
пользователей и данных. Схема перечитывается сама после запроса, который
создает или удаляет коллекции, таблицы и индексы.

Символы и цвета узлов задает секция *[query]* скина: ключи вида
*table-char* и *table*, *item* и *info*. По умолчанию символов и цветов
нет.

**Экспорт**

Ctrl-F6 записывает в файл все строки запроса, который выполнил бы F5, без
*// @limit*, или все строки узла Схемы. Каждая страница диалога - формат:

|  |  |
|--|--|
| CSV | Разделитель, заголовок, кавычки, вид NULL |
| JSON, NDJSON | Массив объектов или объект на строку |
| SQL | INSERT INTO и при желании CREATE TABLE (только PostgreSQL) |
| Markdown | Таблица, ячейка в одну строку |

Строки пишутся во временный файл *.part*, который встает на место нужного,
когда пришли все строки, при этом остановленный или неудавшийся запрос файла
не оставляет. Для CSV и Markdown столбцы MongoDB - ключи первых 200
документов.

**Запрос, написанный ИИ**

F6 берет просьбу - абзац под курсором или выделение, например *заказы за
последнюю неделю по пользователям* - и вставляет под ней запрос ИИ, а
просьбу делает комментарием. Запрос не выполняется. F6 на такой просьбе
пишет запрос заново. Если в абзаце есть запрос пользователя, ИИ пишет новый
запрос после абзаца, не трогая его. F6 во время работы ИИ спрашивает,
остановить ли его.

ИИ получает имена коллекций, полей, таблиц и столбцов с типами, но не
данные.

|  |  |
|--|--|
| MC_QUERY_AI | Программа ИИ: claude, codex или командная строка |
| ai в [Query] | То же в *~/.config/bluerig/ini* |

claude и codex запускаются без своих инструментов. Другая команда читает
просьбу на stdin и печатает запрос; она запускается без *PGPASSWORD* и
*MC_MONGO_URI* в окружении.

Скрипты, которыми плагин читает схему и пишет DDL, лежат в
*/usr/share/bluerig/query*; одноименный файл в *~/.config/bluerig/query* или
*/etc/bluerig/query* выполняется вместо него.

**MongoDB**

Запросы выполняет *mongosh*, дополнение дает языковой сервер *mongolsp*
(<https://github.com/blue-panels/mongolsp/releases>). Первые строки Вывода
говорят, найдены ли они.

|  |  |
|--|--|
| MC_MONGO_URI | Строка подключения, *mongodb://user:password@host:port/* |
| MC_MONGO_DB | База данных; по умолчанию - из строки подключения |
| MC_MONGOSH | Программа mongosh; по умолчанию - из PATH |

Строка *use("name")* выполняет запросы после нее в этой базе. Если ее в
файле нет, *-Q* добавляет ее в начало файла. Сам запрос виден в командной
строке mongosh, поэтому секреты лучше брать из окружения: *process.env.NAME*.

**PostgreSQL**

Запросы выполняет библиотека *libpq5*, дополнение дает
*postgres-language-server*. bluerig держит одно подключение, при этом
транзакция, временные таблицы и *SET* живут от одного F5 до другого.

Куда подключаться, libpq берет из окружения, как *psql*: *PGHOST*,
*PGPORT*, *PGUSER*, *PGDATABASE*, *PGSERVICE*. Пароль лучше держать в
*~/.pgpass*, чем в *PGPASSWORD*.

|  |  |
|--|--|
| MC_QUERY_READ_ONLY=1 | Транзакции только для чтения, *[RO]* в заголовке |
| MC_PG_SCHEMA | Схема, которая в Схеме и у языкового сервера идет первой |
| MC_PG_RELATION | Таблица, первые 100 строк которой выполняются при запуске |

*[RO]* защищает от промаха, но не заменяет права: *SET* его снимает.
*CREATE DATABASE*, *VACUUM* и подобные выполняются отдельным выделением.
Команды psql (`\d`, `\copy`) не работают.
