# Query <!-- help:notitle -->

**Запросы**

Плагин для выполнения запросов к MongoDB и PostgreSQL. Работает только в
режиме запросов (*bluerig -Q*).

|  |  |
|--|--|
| F5 | Выполнить помеченный текст. Если ничего не помечено, в MongoDB будет выполнена секция под курсором (от строки *// ---* до следующей), если она есть. В остальных случаях будет выполнен весь файл |
| Ctrl-F5 | Выполнить весь файл |
| F5, Esc | Во время запроса: предложить остановить его |
| F6 | Написать запрос с помощью ИИ |
| Ctrl-F6, Alt-X | Экспортировать результат запроса в файл |
| Ctrl-Alt-S | Показать или спрятать окно Схема |
| Ctrl-Alt-PgDn, Ctrl-Alt-PgUp | Следующая, предыдущая вкладка ответа |
| F11 | Меню запросов |

Клавиши можно переназначить в секции *[query]* файла *~/.config/bluerig/keymap.ini*.
Команды есть и в меню Запрос. Пункт **Roll back** меню Запрос выполняет
*ROLLBACK*; клавишу для него можно задать там же.

Базу данных выбирает переменная *MC_QUERY_KIND* со значением *mongo*
или *postgres*. Если она не задана, наличие *MC_MONGO_URI* выбирает
MongoDB. Если этой переменной тоже нет, файл *.sql* выбирает PostgreSQL.
Если файл не указан, запросы хранятся в
*~/.local/share/bluerig/queries/*, в файле с именем базы, а для PostgreSQL -
в *postgres/*, в файле с именем подключения и базы.

**Файл запросов**

В MongoDB строка *// ---* начинает новый запрос, а слова после чёрточек
служат его названием. В PostgreSQL запросы выполняются одной транзакцией,
если в файле нет своего *BEGIN*.

```
// --- the last orders
// @table
db.orders.find({ status: 1 }).sort({ ts: -1 })

// --- how many
db.orders.countDocuments({ status: 1 })
```

|  |  |
|--|--|
| // @table | Показать результат последнего выражения во вкладке Таблица |
| // @limit 20 | Вернуть не больше 20 документов; без числа - не больше 100 |

*@limit* добавляет *.limit()* к *find()* или стадию *$limit* к
*aggregate()*, при этом файл остаётся как есть.

**Вкладки ответа**

|  |  |
|--|--|
| Вывод | Что напечатала база: строки запроса, время, сервер, ошибки |
| Таблица | Документы или строки по столбцам: первые 100, посчитаны все |
| История | Версии файла запросов |

Ошибка помечает свою строку в файле, и курсор переходит туда. В PostgreSQL
первая строка Вывода показывает и состояние транзакции: *[TX]*, пока она
открыта, и *[СБОЙ ТРАНЗАКЦИИ: нужен ROLLBACK]*, когда её команда не
удалась.

При запуске плагин сохраняет новую версию файла, если текст изменился
с последней сохранённой версии. В *~/.local/share/bluerig/queries/.history/*
хранится до 200 версий на файл. В Истории:

|  |  |
|--|--|
| Enter, двойной щелчок | Вернуть файл к этой версии (Undo отменяет) |
| F3 | Сравнить версию с файлом (diff -u во вкладке Вывод) |
| F5 | Выполнить запрос версии, не меняя файл |
| Ctrl-Ins | Скопировать отмеченный текст |

Перед переходом к версии текущий текст сохраняется в Истории строкой
*текущая*; Enter на ней возвращает его.

**Меню запросов**

F11 открывает меню запросов в безымянном окне и в файле с расширением
текущей базы: *.js* для MongoDB, *.sql* для PostgreSQL. В меню есть
EXPLAIN запроса, число строк запроса, строки *// @table* и *// @limit*,
перевод помеченного текста в верхний или нижний регистр и правка меню.

Плагин загружает меню из *~/.config/bluerig/query/query-menu.ini*. Если его
нет, ищет *query-menu.ini* сначала в системном каталоге настроек (обычно
*/etc/bluerig/query*), затем в каталоге данных bluerig. Пункт может
запускать свою команду: она получает запрос на стандартный ввод и вид базы
в *BLUERIG_QUERY_KIND*. Пункт EXPLAIN в PostgreSQL добавляет
*EXPLAIN (ANALYZE, BUFFERS)*, если первое слово запроса - *SELECT*,
*VALUES* или *TABLE*. В остальных случаях добавляет *EXPLAIN*.

**Схема**

Ctrl-Alt-S показывает справа дерево базы. Для MongoDB - базы, коллекции с
числом документов, представления, временные ряды, а у раскрытой коллекции -
поля по выборке из 100 документов, индексы и валидатор. Для PostgreSQL -
схемы, таблицы, представления, последовательности и функции, а у раскрытого
отношения - столбцы, ключи, внешние ключи, индексы, ссылки и триггеры.

|  |  |
|--|--|
| Enter, Right, Left | Раскрыть или свернуть узел |
| F5 | Первые 100 строк во вкладку Таблица |
| F3 | Вставить запрос строк в файл запросов |
| F4 | Вставить DDL в файл запросов: DROP (закомментирован) и CREATE |
| Insert | Вставить имя узла у курсора |
| Ctrl-F6, Alt-X | Записать все строки в файл |
| F2 | Подключиться заново и перечитать схему |
| F10, Esc | Закрыть окно |

F4 вставляет DDL объекта: закомментированный *DROP* и *CREATE*, без
владельца, прав и данных. Схема перечитывается сама после запроса, который
создаёт или удаляет коллекции, таблицы и индексы.

Символы и цвета узлов задаёт секция *[query]* скина: ключи вида
*table-char* и *table*, *item* и *info*. По умолчанию символов и цветов
нет.

**Экспорт**

Ctrl-F6 экспортирует результат запроса, который выполнился бы по F5,
или все строки узла Схемы. При экспорте из MongoDB директива *// @limit*
игнорируется. В PostgreSQL экспортируется только первый табличный
результат, даже если в нём нет строк. Остальные результаты можно
посмотреть во вкладке Таблица. Страницы диалога соответствуют форматам:

|  |  |
|--|--|
| CSV | Разделитель, заголовок, кавычки, вид NULL |
| JSON, NDJSON | Массив объектов или объект на строку |
| SQL | INSERT INTO и при желании CREATE TABLE (только PostgreSQL) |
| Markdown | Таблица, ячейка в одну строку |

Плагин пишет строки во временный файл *.part* и переименовывает его
в выбранный файл после успешного завершения экспорта. При отмене или
ошибке временный файл удаляется. Для CSV и Markdown столбцы MongoDB - ключи
первых 200 документов.

**Запрос, написанный ИИ**

F6 берёт промпт из абзаца под курсором или из помеченного текста, например
*заказы за последнюю неделю по пользователям*. Под ним вставляется запрос,
написанный ИИ, а сам промпт становится комментарием. Запрос не выполняется.
F6 на таком промпте пишет запрос заново. Если в абзаце есть запрос пользователя, ИИ пишет новый
запрос после абзаца, не трогая его. F6 во время работы ИИ спрашивает,
остановить ли его.

ИИ получает имена коллекций, полей, таблиц и столбцов с типами, но не
данные.

|  |  |
|--|--|
| MC_QUERY_AI | Программа ИИ: claude, codex или командная строка |
| ai в [Query] | Команда из *~/.config/bluerig/ini*, если *MC_QUERY_AI* не задана или пуста |

claude и codex запускаются без своих инструментов. Другая команда читает
промпт на stdin и печатает запрос. Из окружения команды исключаются
*PGPASSWORD*, *MC_MONGO_URI* и *BLUERIG_PG_URI*.

Скрипты, которыми плагин читает схему и пишет DDL, лежат в
*/usr/share/bluerig/query*; одноимённый файл в *~/.config/bluerig/query* или
*/etc/bluerig/query* выполняется вместо него.

**MongoDB**

Запросы выполняет *mongosh*, дополнение даёт языковой сервер *mongolsp*
(<https://github.com/blue-panels/mongolsp/releases>). Первые строки Вывода
сообщают, найдены ли они.

|  |  |
|--|--|
| MC_MONGO_URI | Строка подключения, *mongodb://user:password@host:port/* |
| MC_MONGO_DB | База данных; по умолчанию - из строки подключения |
| MC_MONGOSH | Программа mongosh; по умолчанию - из PATH |

Строка *use("name")* выполняет запросы после неё в этой базе. Если её в
файле нет, плагин добавляет её в начало файла. Сам запрос виден в командной
строке mongosh, поэтому секреты лучше брать из окружения: *process.env.NAME*.

**PostgreSQL**

Запросы выполняет библиотека *libpq*, дополнение даёт
*postgres-language-server*. bluerig держит одно подключение, при этом
транзакция, временные таблицы и *SET* сохраняются между запусками F5.

Параметры подключения libpq берёт из окружения, как *psql*: *PGHOST*,
*PGPORT*, *PGUSER*, *PGDATABASE*, *PGSERVICE*. Пароль лучше держать в
*~/.pgpass*, чем в *PGPASSWORD*.

|  |  |
|--|--|
| MC_QUERY_READ_ONLY=1 | Транзакции только для чтения, *[RO]* в заголовке |
| MC_PG_SCHEMA | Схема, которая в Схеме и у языкового сервера идёт первой |
| MC_PG_RELATION | Таблица, первые 100 строк которой показываются при запуске |

*[RO]* защищает от промаха, но не заменяет права: *SET* его снимает.
*CREATE DATABASE*, *VACUUM* и подобные выполняются отдельно: пометьте только
их и нажмите F5.
Команды psql (`\d`, `\copy`) не работают.
