# НАИМЕНОВАНИЕ <!-- help:skip -->

bluerig - консольная среда разработки.

# СИНТАКСИС <!-- help:skip -->

**bluerig**
[ключи] [+строка] [файл1[:строка]] [файл2[:строка]] ...

# ОПИСАНИЕ <a id="description"></a>

**bluerig** - консольная среда разработки, выросшая из mcedit (GNU Midnight Commander) и cooledit Пола Шира (Paul Sheer). **brg** - короткое имя той же программы.

Редактор позволяет работать с несколькими файлами одновременно, каждый в своём окне, в том числе с двоичными. Умеет выделять вертикальные блоки, фильтровать строки, сворачивать текст, записывать макросы, передавать текст через команды оболочки из меню пользователя и выполнять скрипты на Lua. Плагины добавляют функциональность работы с проектами, сборкой и отладкой, отображением покрытия кода, языковыми серверами (LSP), git и навигацией по коду, а также проверку правописания.

Поддержка языков расширяема: подсветка синтаксиса, сборка, отладка через адаптеры DAP и языковые серверы настраиваются для каждого языка. В базовой конфигурации есть подсветка более чем для 100 типов файлов, сборка для C (Meson, CMake и Make), Rust и Go, отладка для C, Rust, Python, Bash, Go и JavaScript.

# ОПЦИИ <a id="options"></a>

*+номер*
: Перейти к строке с этим номером (между знаком
*+*
и числом не должно быть пробела). Номеров можно указать несколько, но взят
будет последний, и только для первого файла.

*файл:номер[:]*
: Открыть файл на этой строке - так место в файле печатают компиляторы и
grep. Если существует файл с таким полным именем, вместе с двоеточием и
числом, открывается он.

**Режимы приложения**

*-Q, --query*
: Открыть файл в режиме запросов к MongoDB или PostgreSQL. Задайте
*MC_QUERY_KIND=mongo* или *MC_QUERY_KIND=postgres*. Если эта переменная
не задана, наличие *MC_MONGO_URI* выбирает MongoDB, а файл с расширением
*.sql* выбирает PostgreSQL при отсутствии *MC_MONGO_URI*.
Нужен плагин Query.

*-D каталог, --debug=каталог*
: Открыть проект в режиме отладки. Показывает дерево проекта и панель
отладчика. Нужны плагины Project, Build и Debugger.

*-G каталог, --git=каталог*
: Открыть окно Git для указанного каталога. При закрытии окна bluerig
завершается. Можно указать один из следующих ключей. Без *--git* этот
ключ применяется к текущему каталогу.

**Опции Git**

*--git-log*
: Открыть историю коммитов.

*--git-show=коммит*
: Показать файлы и изменения указанного коммита.

*--git-commit*
: Открыть редактор сообщения для коммита подготовленных изменений.

*--git-amend*
: Изменить последний коммит, добавив подготовленные изменения.
Открывает редактор сообщения коммита.

*--git-reword=коммит*
: Открыть редактор сообщения указанного коммита. Сохранение сообщения
переписывает историю Git.

**Общие опции**

*-V, --version*
: Показать версию программы.

*-f, --datadir*
: Показать вкомпилированные пути поиска файлов данных bluerig.

*-F, --datadir-info*
: Показать подробные сведения о каталогах, с которыми работает bluerig: о
файлах данных, файлах пользователя и плагинах.

*--configure-options*
: Показать ключи, с которыми программа была сконфигурирована.

*--no-lua*
: Запуститься без среды Lua: ни один Lua-скрипт не загружается.

*-h, -?, --help*
: Показать параметры командной строки и их описание.

*--help-all*
: Показать параметры командной строки всех групп.

*--help-terminal, --help-color*
: Показать параметры терминала или цветового режима.

**Опции терминала**

*-x, --xterm*
: Включить режим xterm. Применяется на терминалах, которые умеют то же, что и
xterm: два режима экрана и последовательности мыши.

*-X, --no-x11*
: Не обращаться к X Window System за состоянием клавиш-модификаторов.

*-g, --oldmouse*
: Использовать старый способ отслеживания мыши терминалом.

*-d, --nomouse*
: Отключить поддержку мыши.

*-t, --termcap*
: Брать сведения о терминале из termcap, а не из terminfo. Ключ есть только
тогда, когда bluerig собран с библиотекой S-Lang.

*-s, --slow*
: Работа на медленном терминале: экран перерисовывается реже.

*-a, --stickchars*
: Рисовать рамки простыми символами вместо псевдографики терминала.

*-K файл, --keymap=файл*
: Загрузить привязки клавиш из этого файла. Смотрите
[Переопределение клавиш](#keys_redefine).

*--nokeymap*
: Не загружать никаких файлов раскладки: использовать привязки клавиш,
встроенные в программу.

**Опции цветового режима**

*-b, --nocolor*
: Черно-белый режим отображения.

*-c, --color*
: Цветной режим на терминалах, которые не сообщают о поддержке цвета.

*-S скин, --skin=скин*
: Использовать скин с этим именем. Смотрите
[Скины](#skins).

# Общий вид <a id="overview"></a>

Вверху экрана bluerig находится
[строка меню](#menu-bar),
под ней окна редактора, а внизу - надписи функциональных клавиш. Строка меню
может быть скрыта: F9 или щелчок по верхней строке экрана вызывают ее.

В строке состояния вверху окна указаны имя файла, его состояние и положение
курсора. Меню [Окно](#window-menu) позволяет переключаться между открытыми
окнами. Окна можно перемещать и менять их размер.

## Переопределение клавиш <a id="keys_redefine"></a>

|  |  |
|--|--|
| Настройки \> [Привязки клавиш](#key-bindings) | Назначить действию свои клавиши; хранятся в **~/.config/bluerig/keymap.ini** |
| Настройки \> [Распознавание клавиш](#learn-keys) | Назначить клавишам управляющие последовательности |
| Настройки \> [Анализатор клавиш](#key-sniffer) | Показать, что присылает терминал при нажатии и какое действие назначено на клавишу |

При запуске bluerig берёт встроенную раскладку и загружает поверх неё
**{{pkgdatadir}}/keymap.ini**,
затем
**{{sysconfdir}}/bluerig/keymap.ini**.
Действие, указанное в файле, получает клавиши из файла, при этом его
встроенные клавиши перестают работать.

Пакет устанавливает в
**{{sysconfdir}}/bluerig**
раскладки
**keymap.default.ini**,
**keymap.emacs.ini**
и
**keymap.vim.ini**
и создаёт
**keymap.ini**
как ссылку на
**keymap.default.ini**.

Ключ
**--nokeymap**
отключает загрузку файлов, при этом работает только встроенная раскладка.

Источники пользовательской раскладки в порядке приоритета:

```
1) ключ командной строки -K <раскладка>, --keymap=<раскладка>
2) переменная окружения BLUERIG_KEYMAP
3) параметр keymap секции [bluerig] ini-файла
4) файл ~/.config/bluerig/keymap.ini
```

Первые три принимают имя или абсолютный путь. К имени, которое не
оканчивается на
**.keymap**,
bluerig добавляет это расширение. Каталоги поиска в порядке приоритета:

```
1) ~/.config/bluerig/
2) {{pkgdatadir}}/
```

Ключ
**-K**,
переменная
**BLUERIG_KEYMAP**
и параметр
**keymap**
добавляют к имени расширение
**.keymap**,
если его нет, при этом раскладки пакета с расширением
**.ini**
так не выбрать. Чтобы включить одну из них, создайте на неё ссылку
**~/.config/bluerig/keymap.ini**:
этот файл загружается, когда ни один из трёх способов не задан.

```
ln -s {{sysconfdir}}/bluerig/keymap.vim.ini ~/.config/bluerig/keymap.ini
```

Секции файла раскладки:

|  |  |
|--|--|
| [editor] | Редактор |
| [editor:xmap] | Клавиши после префикса, действие ExtendedKeyMap |
| [dialog] | Диалоги |
| [menu] | Меню |
| [input] | Строки ввода |
| [listbox] | Списки |
| [radio] | Переключатели |
| [help] | Окно помощи |
| [mcterm] | Терминал |

Строка секции задаёт действие и его клавиши через точку с запятой:

```
[editor]
Save = f2
SaveAs = f12; ctrl-f2
```

# Поддержка мыши <a id="mouse-support"></a>

bluerig поддерживает мышь. Она работает всегда, когда программа запущена в
терминале
**xterm(1)**
(даже если из xterm открыто соединение telnet или ssh с другой машиной) или
на консоли Linux с запущенным сервером мыши
**gpm**.

Щелчок по тексту перемещает курсор, а перетаскивание выделяет текст.
Мышью можно открывать меню, нажимать кнопки и вызывать команды, указанные
в нижней строке экрана. Колесо мыши прокручивает текст.

По умолчанию кнопки мыши повторяют нажатие каждые 400 миллисекунд. Это
значение меняет параметр
*mouse_repeat_rate*
ini-файла, а время, в пределах которого два щелчка считаются двойным, -
параметр
*double_click_speed*.

Если bluerig работает с поддержкой мыши, обычное поведение мыши терминала
(выделение и вставка текста) получается при нажатой клавише Shift.

# Строка меню <a id="menu-bar"></a>

Строка меню появляется по {{key:Menu|F9}} или по щелчку мышью по верхней строке экрана.
В ней меню Файл, Правка, Поиск, Команда, Навигация (если в него что-то
добавил плагин или скрипт), Окно, Плагины и Настройки. Lua-скрипт может

### Режим сохранения <a id="edit-save-mode"></a>

Как записывается файл - те же три режима, что принимает параметр
*editor_option_save_mode*:

**Быстрое сохранение**
: Записывать данные сразу в исходный файл. При сбое записи файл может
остаться неполным.

**Безопасное сохранение**
: Записывать данные во временный файл и заменять им исходный только после
завершения записи.

**Создавать резервные копии с расширением**
: Безопасное сохранение, и оригинал сохраняется под своим именем с
добавленным расширением из строки ввода, по умолчанию "~". Вторая запись
заменяет и резервную копию.

**Проверять перевод строки POSIX**
: Спрашивать о недостающем переводе строки в конце файла перед записью.

# Поиск, замена и фильтр строк <a id="search-and-replace"></a>

{{key:Search|F7}} открывает диалог поиска.

|  |  |
|--|--|
| Обычный | Ищет строку как есть |
| Регулярное выражение | Ищет по регулярному выражению |
| Шестнадцатеричный | Ищет байты, записанные шестнадцатеричными числами |
| По шаблону | Ищет по шаблону оболочки с \* и ? |
| С учётом регистра | Различает строчные и заглавные буквы |
| Назад | Ищет от курсора к началу файла |
| В выделенном | Ищет только в выделенном блоке |
| Слово целиком | Находит совпадение, только если это целое слово |
| Все кодировки | Ищет во всех кодировках, в которых может быть записан файл |
| Найти всё | Ставит закладку на каждой строке с совпадением |
| Фильтр | Скрывает строки без совпадения |

{{key:Replace|F4}} открывает диалог замены: те же поля и строка «Введите текст
для замены». При замене по регулярному выражению \\1 - \\9 подставляют группы
совпадения.

|  |  |
|--|--|
| Заменить | Заменяет это совпадение и ищет следующее |
| Все | Заменяет все совпадения без вопросов |
| Пропустить | Оставляет это совпадение и ищет следующее |

**Фильтр**

Фильтр скрывает строки без совпадений, сохраняя нумерацию. В колонке
состояния отмечены скрытые участки. Фильтр применяется в момент включения.
Новые и изменённые строки остаются видимыми до следующего применения
фильтра.

|  |  |
|--|--|
| {{key:FilterToggle|Alt-s}} | Снимает фильтр или применяет результаты последнего поиска. Если поиска ещё не было, открывает диалог поиска |
| {{key:FilterWord|Alt-S}} | Фильтрует по выделенному тексту или по слову под курсором |
| Команда \> Развернуть всё | Снимает фильтр и все свёртки |

# Свертка <a id="folding"></a>

При свёртке видна только первая строка блока. В колонке состояния рядом
с ней появляется отметка.
{{key:FoldToggle|Alt-F}}
(пункт «Свернуть / развернуть блок» меню «Команда») сворачивает выделенные
строки, а если ничего не выделено, - строки от скобки в текущей строке до
парной к ней. На первой строке свертки эта клавиша ее разворачивает.
**Развернуть всё**
открывает все свертки файла и снимает фильтр строк.

# Макросы <a id="macros"></a>

{{key:MacroStartStopRecord|Ctrl-r}}
начинает запись макроса. Чтобы завершить запись, снова нажмите
{{key:MacroStartStopRecord|Ctrl-r}},
затем нажмите клавишу, которой будете запускать макрос.

Макросы хранятся в секции
**[editor]**
файла
**~/.local/share/bluerig/macros**.
Чтобы удалить макрос, удалите его строку из файла или воспользуйтесь
[Обозревателем макросов](#macro-explorer).

Пункт
**Записать/повторить действия**
меню "Команда" записывает последующие действия, пока его не выберут снова,
а затем спрашивает, сколько раз их повторить.

На клавишу можно назначить и скрипт оболочки, строкой файла
**macros**
такого вида:

```
[editor]
Ctrl-W=ExecuteScript:25;
```

Это значит, что Ctrl-W запускает действие
*ExecuteScript(25)*,
которое выполняет скрипт оболочки
**~/.local/share/bluerig/macros.d/macro.25.sh**.
Скрипты лежат в каталоге
**~/.local/share/bluerig/macros.d/**
и называются
**macro.XXXX.sh**,
где
**XXXX**
\- число от 0 до 9999. Примеры установлены в
**{{pkgdatadir}}/examples/macros.d/**.
Скрипт записывается в формате пунктов
[меню пользователя](#edit-menu-file)
и принимает те же подстановки. Его первой строкой может быть

*#silent*
: Скрипт запускается, не спрашивая параметров.

Вот пример скрипта:

```
l       comment selection
	TMPFILE=`mktemp ${BLUERIG_TMPDIR:-/tmp}/up.XXXXXX` || exit 1
```

# Меню пользователя <a id="edit-menu-file"></a>

{{key:UserMenu|F11}}
открывает меню пользователя: каждый его пункт - скрипт оболочки, который
выполняется над текстом редактора. Меню читается из первого найденного файла:

```
1) ./.bluerig.menu в текущем каталоге
2) ~/.config/bluerig/menu
3) ~/bluerig.menu
4) {{sysconfdir}}/bluerig/bluerig.menu
5) {{pkgdatadir}}/bluerig.menu
```

Файл текущего каталога читается, только если он принадлежит пользователю или
root и никто другой не может в него писать: его пункты выполняют команды.
Пункт
**Файл меню**
меню "Настройки" открывает файл меню в редакторе.

Строка, которая начинается не с пробела и не с табуляции, - пункт меню, её
первый символ - горячая клавиша пункта. Строки, которые начинаются с пробела
или табуляции, - команды пункта. Строка, которая начинается с '#', -
комментарий.

При выборе пункта его команды записываются во временный файл, и оболочка
выполняет этот файл, при этом в командах заменяются подстановки:

|  |  |
|--|--|
| %f, %p, %s | Имя текущего файла |
| %n | Имя текущего файла без расширения |
| %x | Расширение имени текущего файла |
| %d | Текущий каталог |
| %c | Положение курсора в файле |
| %i | Отступ из пробелов, равный колонке курсора |
| %y | Тип синтаксиса текущего файла |
| %b | Файл блока: выделенный текст записывается в **~/.cache/bluerig/block** перед запуском, а то, что команды оставят там, заменяет блок |
| %m | Имя файла меню |
| %% | Символ % |
| %{текст} | Строка ввода с подсказкой "текст"; подставляется введённое, Esc или F10 отменяют пункт |
| %view | Открывает стандартный вывод команд в новом окне редактора; слова в фигурных скобках после него, как в %view{ascii}, пропускаются |

Заглавные и строчные буквы подстановок означают одно и то же. Число после %
включает (по умолчанию) или выключает экранирование: %f и %1f экранируют
подставленное значение, %0f - нет.

Пример файла меню:

```
s       Sort the block
	sort %b > %b.tmp && mv -f %b.tmp %b

w       Count the words of the file
	%view wc %f

m       Run make in the directory of the file
	make
```

**Пункт по умолчанию**

Строка, которая начинается с '=' в первой колонке, - условие пункта под ней:
если условие истинно, пункт становится пунктом по умолчанию.

```
Синтаксис условия:  = <подусловие>
  или:              = <подусловие> | <подусловие> ...
  или:              = <подусловие> & <подусловие> ...

Подусловие - одно из:

  y <шаблон>    синтаксис текущего файла подходит?
  f <шаблон>    текущий файл подходит под шаблон?
  d <шаблон>    текущий каталог подходит под шаблон?
  t <тип>       текущий файл этого типа?
  x <имя>       этот файл исполняемый?
  ! <подусл.>   отрицание подусловия
```

Шаблон - шаблон оболочки или регулярное выражение, смотря по параметру
*shell_patterns*;
строка "shell_patterns=0" или "shell_patterns=1" первой строкой файла меню
задаёт его для этого файла.

Тип - один или несколько символов:

```
  n   не каталог
  r   обычный файл
  d   каталог
  l   ссылка
  c   символьное устройство
  b   блочное устройство
  f   FIFO (канал)
  s   сокет
  x   исполняемый файл
```

Например, 'rlf' - обычный файл, ссылка или FIFO.

Условие, которое начинается с '=?' вместо '=', при каждом вычислении
показывает отладочную трассировку.

Условия вычисляются слева направо, без старшинства '&' над '|':

```
	= f *.c | f *.h & y C
```

вычисляется как

```
	( (f *.c) | (f *.h) ) & (y C)
```

**Условия добавления**

Условие, которое начинается с '+' (или '+?'), включает пункт в меню, только
если оно истинно. Условие с '+=' или '=+' ('+=?' и '=+?' с трассировкой)
действует и как условие добавления, и как условие по умолчанию. Две строки
условий перед пунктом, с '+' и с '=', задают их по отдельности.

## Раздел file <a id="syntax-file"></a>

Файл синтаксиса состоит из разделов. Каждый начинается строкой
**file**
и обычно вынесен в отдельный файл строкой
**include**:

```
file <имя файла> <описание> [<первая строка>]
```

*Имя файла*
и
*первая строка*
\- регулярные выражения: раздел применяется к файлу, если совпало его имя или
первая строка текста.
*Описание*
\- имя синтаксиса, в котором пробелы записываются как \s. На это имя ссылаются строки
**embed**
и
**overlay**.
Раздел заканчивается там, где начинается следующий, и делится на контексты с
ключевыми словами.

Простейший раздел для программы на C:

```
file .\*\\.c C\sProgram\sFile (#include|/\\\*)

wholechars abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ_

# цвета по умолчанию
define  comment   brown
context default
  keyword  whole  if       yellow
  keyword  whole  else     yellow
  keyword  whole  for      yellow
  keyword  whole  while    yellow
  keyword  whole  do       yellow
  keyword  whole  switch   yellow
  keyword  whole  case     yellow
  keyword  whole  static   yellow
  keyword  whole  extern   yellow
  keyword         {        brightcyan
  keyword         }        brightcyan
  keyword         '*'      green

# комментарии C
context /\* \*/ comment

# директивы препроцессора C
context linestart # \n red
  keyword  \\\n  brightred

# строковые константы C
context " " green
  keyword  %d    brightgreen
  keyword  %s    brightgreen
  keyword  %c    brightgreen
  keyword  \\"   brightgreen
```

## Контексты <a id="syntax-contexts"></a>

Контекст - область текста со своим цветом и своими ключевыми словами,
например комментарий C между /\* и \*/. Он начинается строкой:

```
context [exclusive] [oneline] [whole|wholeright|wholeleft] [linestart] <разделитель>
        [linestart] <разделитель> [<цвет>] [<фон>] [<атрибуты>]
```

Первый контекст раздела -
**context default**
[*цвет*] [*фон*] [*атрибуты*],
без него раздел даёт ошибку.

|  |  |
|--|--|
| linestart | Разделитель стоит в начале строки |
| whole | Разделитель - целое слово |
| wholeleft | Слева разделитель стоит на границе слова |
| wholeright | Справа разделитель стоит на границе слова |
| exclusive | Окрашивает текст между разделителями, но не сами разделители |
| oneline | После exclusive: заканчивает контекст в конце строки, если правого разделителя на ней нет |

Строка
**wholechars**
[**left**|**right**] *символы*
в любом месте файла задаёт символы целого слова, левый и правый наборы по
отдельности. Строка
**spellcheck**
после
**context**
включает проверку правописания внутри контекста.

## Вложение и слои <a id="syntax-embed"></a>

Строка

**embed**
[**soft**]
*тип*

после
**context**
применяет к тексту между разделителями правила другого синтаксиса.
*тип*
\- описание из его строки file, с \s вместо пробела. Тип ищется в файле
Syntax, из которого читаются правила, затем в установленном вместе с bluerig.
Если типа нет ни там, ни там, контекст остаётся в своих цветах. Разделители
остаются в цветах контекста. Правый разделитель заканчивает вложенный текст,
где бы он ни встретился, в том числе внутри строки или комментария вложенных
правил. Синтаксисы можно вкладывать в несколько уровней. Например, правила HTML
могут подключать синтаксис JavaScript для содержимого тега SCRIPT:

```
  context <SCRIPT*> </SCRIPT> brightcyan
      embed JavaScript\sProgram
```

С
**soft**
правый разделитель заканчивает вложенный текст только вне строк,
комментариев и ключевых слов вложенных правил, так что в {{ "}}" }} шаблона
Jinja2 первые }} остаются частью строки, а в ${x/\\}/y} shell-скрипта первая
} остаётся частью экранирования.

Строка

**overlay**
*тип*

среди правил делает весь синтаксис слоем поверх
*типа*:
его контексты окрашивают то, что в них, где бы оно ни стояло, а остальной
текст читают правила
*типа*,
которые видят содержимое контекстов пробелами. Так теги языка шаблонов
окрашиваются и в тексте, и внутри HTML-тега, и в строке атрибута, и в скрипте,
а остальное окрашивает HTML. Контекст по умолчанию у слоя ничего не
окрашивает: ключевое слово в нём лишь не даёт начаться контексту. Тип,
которого нет ни в одном файле Syntax, оставляет слой поверх простого текста.
Например, Smarty поверх HTML:

```
  overlay HTML\sFile
  context default
      keyword {\s
  context {\* \*} brown
  context { } brightcyan
      embed soft Smarty\sTag
```

## Ключевые слова <a id="syntax-keywords"></a>

Ключевое слово контекста задаёт строка:

```
keyword [whole|wholeright|wholeleft] [linestart] <строка> [<цвет>] [<фон>] [<атрибуты>]
```

Строки ключевых слов и разделителей контекстов разбираются так:

|  |  |
|--|--|
| \\t, \\s | Табуляция и пробел. В явном виде они служат разделителями, поэтому в шаблоне используются эти обозначения |
| \\n, \\r | Перевод строки и возврат каретки |
| `\\` | Обратная косая черта |
| \\\* | Звёздочка |
| \* | Любые символы, сколько угодно |
| + | Символы слова, сколько угодно, и ни одного тоже |
| \\[abc\\] | Символы из набора, сколько угодно |
| \\{abc\\} | Один символ из набора |

В разделителе контекста шаблон не может стоять первым или последним
символом. Например,

```
  keyword         '*'      green
```

красит односимвольные константы C зелёным, а

```
  keyword         "*"      green
```

красит строковые константы, если они не переходят через перевод строки.

Строка

```
  keyword  \\\n  brightgreen
```

задаёт ключевое слово из обратной косой черты и перевода строки. Ключевые
слова проверяются раньше разделителей контекста, поэтому оно не даёт
контексту закончиться в конце строки с обратной косой чертой, и директива
препроцессора C продолжается на нескольких строках.

Строка
**define**
*имя слова...*
задаёт имя, которое в правилах заменяет эти слова, например
**define comment brown**.

## Цвета и атрибуты <a id="syntax-colors"></a>

Цвета: black, gray, red, brightred, green, brightgreen, brown, yellow, blue,
brightblue, magenta, brightmagenta, cyan, brightcyan, lightgray и white.
"default" - цвет терминала по умолчанию, "base" - основные цвета редактора,
он задаёт атрибуты, не меняя цвета фона. При 256 цветах есть и color16 -
color255, rgb000 - rgb555, gray0 - gray23.

Вместо цвета текста можно указать токен области (scope token): слово
заглавными буквами, обозначающее тип текста. Его цвет задаёт скин:

```
keyword  whole  if   KEYWORD_CONTROL
context  " " STRING_QUOTED_DOUBLE
    keyword  \\"   CONSTANT_CHARACTER_ESCAPE
keyword  linestart TODO  KEYWORD_OTHER_TODO black
```

Скин задаёт цвета интерфейса и токенов подсветки для всех языков. См.
[Скины](#skins).
Имя области записывается строчными буквами с точками вместо
подчёркиваний. Например, KEYWORD_CONTROL_IMPORT - это keyword.control.import,
разновидность keyword.control, а та - разновидность keyword. Это имена
областей Sublime Text и TextMate. Фон и атрибуты в скине имеют приоритет
перед значениями, указанными после токена в правиле. Если скин их
не задаёт, берутся значения из правила, например black выше. Остальные
значения берутся из стандартной схемы mcedit. Токен работает и в define, и в строках number, string и symbols правил
line-local. Установленные файлы синтаксиса используют токены. Список токенов и
соответствующих им цветов mcedit приведён в
**{{pkgdatadir}}/syntax/README.txt**.

Файл синтаксиса, общий с
**cooledit**,
задаёт цвета для обоих через косую черту, bluerig берёт цвет до неё:

```
keyword  #include  red/Orange
```

Атрибуты - bold, italic, underline, reverse и blink, несколько соединяются
знаком плюс.

## Прочие строки <a id="syntax-other"></a>

|  |  |
|--|--|
| # ... | Комментарий, отдельной строкой |
| caseinsensitive | В начале файла: регистр букв не важен |
| line-local | Режим для обычного текста: сбрасывается на каждом переводе строки и на границе экрана и разбирает только показанный текст |
| number *макс* *цвет* | В line-local: десятичные числа до *макс* цифр |
| string *кавычка* *цвет* | В line-local: строки в одинарных или двойных кавычках |
| symbols *символы* *цвет* | В line-local: отдельно раскрашиваемые знаки препинания |

# Цвета <a id="colors"></a>

bluerig пытается определить, поддерживает ли терминал цвет, по базе данных
терминалов и имени терминала. Иногда он ошибается, поэтому цветной режим
можно включить ключом -c или выключить ключом -b.

Если программа собрана с экранной библиотекой S-Lang, а не с ncurses, она
проверяет еще и переменную
**COLORTERM**:
если она задана, это действует так же, как ключ -c.

Терминалы, для которых цветной режим включается всегда, можно перечислить в
переменной
*color_terminals*
секции Colors ini-файла. Тогда bluerig не будет пытаться определить, есть ли у
терминала цвет. Пример:

```
[Colors]
color_terminals=linux,xterm
color_terminals=terminal-name1,terminal-name2...
```

Программа может быть собрана и с ncurses, и с S-Lang; ncurses не дает
способа принудительно включить цвет: она пользуется только сведениями из
базы данных терминалов.

# Скины <a id="skins"></a>

Цвета программы и линии ее рамок берутся из файла скина. Диалог
[Внешний вид](#appearance)
выбирает скин из списка.

Если в скине есть определения true color, в секции [skin] нужно задать ключ
'truecolors' со значением TRUE. Если true color не используется, а 256
цветов используются, нужно задать '256colors'.

Источники выбора скина в порядке приоритета:

```
1) ключ командной строки -S <скин>, --skin=<скин>
2) переменная окружения BLUERIG_SKIN
3) параметр skin секции [bluerig] ini-файла
4) скин с именем default
```

Имя может быть абсолютным путем к файлу скина (с расширением .ini или без
него). Иначе bluerig ищет файл скина в следующем порядке:

```
1) ~/.local/share/bluerig/skins/
2) {{sysconfdir}}/bluerig/skins/
3) {{pkgdatadir}}/skins/
```

Формат файлов скинов описан в
**{{pkgdatadir}}/skins/README.txt**.
Цвета подсветки синтаксиса берутся из секции
**[syntax]**
скина. Ключ задаёт цвет области (scope). Чтобы задать цвет области внутри
контекста, укажите через пробел сначала область контекста, затем область
текста. В каждом случае выбирается самое длинное подходящее имя области.
Сочетание с контекстом проверяется первым.

```
[syntax]
    comment = gray
    keyword = yellow
    keyword.control = brightmagenta
    string = green
    string constant.character.escape = white;red
    invalid = white;red;bold
```

Для областей без цвета в скине используются стандартные цвета mcedit.
Явно заданные в правилах подсветки цвета сохраняются при любом скине. См.
[Подсветка синтаксиса](#syntax-highlighting).

# Базы данных терминалов <a id="terminal-databases"></a>

bluerig позволяет переопределить настройки терминала для текущего
пользователя без прав root.
Диалог
[Распознавание клавиш](#learn-keys)
записывает управляющие последовательности в
**~/.config/bluerig/term/\<TERM>**,
по строке на клавишу в секции
**[keys]**.
Кроме того, bluerig ищет в системном файле
**defaults.ini**
(в
**{{sysconfdir}}/bluerig**
или
**{{pkgdatadir}}**)
и в файле
**~/.config/bluerig/ini**
секцию "terminal:имя-вашего-терминала", а затем секцию "terminal:general".
Каждая строка секции содержит обозначение клавиши, знак равенства и
определение клавиши. Символ escape записывается как \\e, а control-x - как
^x. Строка
*copy=другой*
подключает все определения клавиш из секции «terminal:другой».

Возможные обозначения клавиш:

```
f0 - f20      функциональные клавиши f0-f20
bs            backspace
home          клавиша home
end           клавиша end
up            стрелка вверх
down          стрелка вниз
left          стрелка влево
right         стрелка вправо
pgdn          page down
pgup          page up
insert        клавиша insert
delete        клавиша delete
complete      автодополнение
```

Например, чтобы клавиша insert означала Escape + [ + O + p, запишите в
ini-файл:

```
insert=\e[Op
```

Обозначение клавиши может включать модификаторы:

```
    ctrl-alt-right=\e[[1;6C
    ctrl-alt-left=\e[[1;6D
```

Это значит, что ctrl+alt+left посылает последовательность \\e[[1;6D, и
bluerig понимает "\\e[[1;6D" как Ctrl-Alt-Left.

Обозначение
*complete*
задаёт управляющие последовательности для автодополнения. Обычно для этого
используется Alt-Tab. Можно указать последовательность другой клавиши.

# Скрипты на Lua <a id="lua-scripting"></a>

При сборке с поддержкой Lua скрипты могут добавлять команды в меню,
назначать их клавишам, обрабатывать события редактора, открывать диалоги
и полноэкранные окна. На Lua реализованы, например, сортировка строк,
форматирование абзаца, вставка вывода команды, вставка символа по его коду,
вставка даты, декодирование base64 и рисование таблиц.

Системные скрипты лежат в
**{{pkgdatadir}}/lua/scripts/**,
а скрипты пользователя - в
**~/.local/share/bluerig/lua/scripts/**,
по каталогу на скрипт, со своими
**lua.ini**
и
**init.lua**.
Диалог
[Lua-скрипты](#lua-scripts)
включает и выключает их.

Ключ
**--no-lua**
или переменная
**BLUERIG_NO_LUA**,
равная 1, запускают редактор без Lua-скриптов, а
*enabled=false*
в секции
**[Lua]**
ini-файла отключает Lua и при последующих запусках.

Как написать скрипт и какие функции доступны скрипту, описано в
**LUA_PLUGINS.md**
и
**LUA_API_REFERENCE.md**,
которые устанавливаются вместе с документацией bluerig.

# Общие параметры <a id="general-settings"></a>

Эти параметры секции
**[bluerig]**
ini-файла относятся к программе, а не к редактору. Если не сказано иное, 1
включает параметр, а 0 выключает.

*auto_save_setup*
: Записывать настройки в ini-файл при каждом выходе из редактора.

*skin*
: Имя скина. Смотрите [Скины](#skins).

*shadows*
: Рисовать тень под диалогами и выпадающими меню.

*keymap*
: Файл раскладки. Смотрите [Переопределение клавиш](#keys_redefine).

*drop_menus*
: По F9 сразу открывать первое меню, а не только строку меню.

*mouse_close_dialog*
: Щелчок вне диалога закрывает его.

*mouse_repeat_rate, double_click_speed*
: Частота автоповтора кнопок мыши и время, в пределах которого два щелчка
считаются двойным, в миллисекундах.

*old_esc_mode, old_esc_mode_timeout*
: При включенном old_esc_mode одиночное нажатие Esc считается Esc через
old_esc_mode_timeout микросекунд, без ожидания следующей клавиши.

*show_all_if_ambiguous*
: При неоднозначном дополнении сразу показывать список вариантов. Смотрите
[Автодополнение](#completion).

*shell_patterns*
: Шаблоны условий меню пользователя - шаблоны оболочки (1) или регулярные
выражения (0).

*num_history_items_recorded*
: Максимальное число записей в истории каждого поля ввода.

*confirm_history_cleanup*
: Спрашивать перед очисткой истории.

*clear_before_exec*
: Очищать экран перед выполнением команды меню пользователя.

*pause_after_run*
: Ждать нажатия клавиши после выполнения команды меню пользователя: никогда
(0), только на простых терминалах (1, по умолчанию) или всегда (2).

*alternate_plus_minus*
: Оставить клавишам плюс и минус цифровой клавиатуры значения плюса и минуса.

*keybar_modifiers*
: Если включено, линейка клавиш показывает команды Shift, Ctrl или Alt с
F-клавишами, пока этот модификатор нажат. Нужен терминал с протоколом
клавиатуры kitty. bluerig запрашивает у терминала события нажатия и
отпускания клавиш и изменения фокуса. По умолчанию параметр выключен.

*verbose*
: Показывать ход долгих операций.

*keybar_visible*
: В секции
**[Layout]**:
показывать надписи функциональных клавиш внизу экрана.

# ОКРУЖЕНИЕ <a id="environment"></a>

Ниже перечислены переменные, которые читает bluerig. Переменные вроде
**TERM**, **SHELL**, **HOME** или **PATH** здесь не перечислены: программа
читает их, чтобы узнать, где она работает, а не для настройки.

**BLUERIG_DATADIR**
: Каталог, из которого берутся файлы данных, вместо {{pkgdatadir}}. Смотрите
[ФАЙЛЫ](#files).

**BLUERIG_PROFILE_ROOT**
: Абсолютный путь к каталогу, который используется вместо домашнего
для хранения файлов пользователя.
Смотрите [ФАЙЛЫ](#files).

**BLUERIG_SKIN**
: Скин, по имени или по пути. Смотрите [Скины](#skins).

**BLUERIG_KEYMAP**
: Файл раскладки. Смотрите [Переопределение клавиш](#keys_redefine).

**BLUERIG_TMPDIR**, **TMPDIR**
: Каталог для временных файлов программы - первая заданная из двух; если не
задана ни одна, /tmp.

**BLUERIG_NO_LUA**
: Значение 1 запускает программу без среды Lua. Ни один Lua-скрипт не
загружается.

**KEYBOARD_KEY_TIMEOUT_US**
: Сколько ждать продолжения управляющей последовательности, в микросекундах.

**COLORTERM**
: Читается при выборе цветов. Смотрите [Цвета](#colors).

**BLUERIG_LOG_ENABLE**, **BLUERIG_LOG_FILE**
: Отладочный журнал пишется, когда BLUERIG_LOG_ENABLE равна 1. Без
**BLUERIG_LOG_FILE** используется файл, заданный параметром *logfile* секции
*[Logging]* ini-файла, а без него - *~/.cache/bluerig/bluerig.log*.

**BLUERIG_SPELL_LOG**
: Путь к отладочному журналу проверки правописания. Если переменная задана,
проверка правописания записывает журнал в этот файл.

# ФАЙЛЫ <a id="files"></a>

Полные пути, приведенные ниже, в разных установках могут отличаться. На
файлы данных влияет еще и переменная окружения
**BLUERIG_DATADIR**:
если она задана, ее значение используется в путях ниже вместо
{{pkgdatadir}}. Каталоги файлов пользователя определяются настройками XDG:
*~/.config*,
*~/.local/share*
и
*~/.cache*
означают
**XDG_CONFIG_HOME**,
**XDG_DATA_HOME**
и
**XDG_CACHE_HOME**,
если они заданы.

*{{pkgdatadir}}/help/bluerig.md*
: Файл помощи программы (переводы - bluerig.ru.md и т. д.); рядом лежат
файлы помощи плагинов редактора.

*{{sysconfdir}}/bluerig/bluerig.ini*, *{{pkgdatadir}}/bluerig.ini*
: Общесистемные файлы настроек; используются, только если у пользователя нет
своего файла
**~/.config/bluerig/ini**.
Если есть {{sysconfdir}}/bluerig/bluerig.ini, {{pkgdatadir}}/bluerig.ini не
используется.

*{{sysconfdir}}/bluerig/defaults.ini*, *{{pkgdatadir}}/defaults.ini*
: Общие настройки, которые действуют на всех пользователей, независимо от
того, есть у них ~/.config/bluerig/ini или нет. Сейчас из него загружаются
только
[настройки терминалов](#terminal-databases).

*{{sysconfdir}}/bluerig/keymap.ini*, *{{pkgdatadir}}/keymap.ini*
: Общесистемные привязки клавиш. Смотрите
[Переопределение клавиш](#keys_redefine).

*{{sysconfdir}}/bluerig/bluerig.menu*, *{{pkgdatadir}}/bluerig.menu*
: Общесистемное [меню пользователя](#edit-menu-file).

*{{sysconfdir}}/bluerig/spell.keymap, ctags.keymap*
: Клавиши плагинов проверки правописания и ctags; одноименный файл в
~/.config/bluerig переопределяет их.

*{{pkgdatadir}}/syntax/\**
: Общесистемные файлы синтаксиса; используются, только если у пользователя

**~/.local/share/bluerig/syntax/**.

*{{pkgdatadir}}/skins/\**

*{{pkgdatadir}}/charsets*

*{{pkgdatadir}}/lua/scripts/\**

*{{plugins_dir}}/*
: Плагины редактора, загружаемые при работе.

*~/.config/bluerig/ini*
: Собственные настройки пользователя. Если этот файл есть, настройки
читаются из него, а не из общесистемного файла.

*~/.config/bluerig/keymap.ini*
: Собственные привязки клавиш пользователя.

*~/.config/bluerig/menu*
: Собственное [меню пользователя](#edit-menu-file).

: Выключенные плагины и Lua-скрипты.

**BLUERIG_PROFILE_ROOT**.
Ее значение должно быть абсолютным путем. Если BLUERIG_PROFILE_ROOT не задана
или пуста, используется переменная HOME. Если не задана или пуста и HOME,
каталоги берутся у библиотеки GLib.
